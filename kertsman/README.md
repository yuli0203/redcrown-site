# קרצמן נדל"ן — אתר משרד התיווך / Kertsman Real Estate — office website

אתר סטטי של משרד תיווך בוטיק באזור חיפה. ללא שלב בנייה ובלי תלות בשרת:
HTML, CSS, JS, פונטים ותמונות בלבד.
אפשר להעלות את תיקיית `kertsman/` כמו שהיא לשורש הדומיין (GoDaddy File Manager,
FTP או כל אחסון סטטי) — כל הקישורים יחסיים ולכן שום דבר לא נשבר בדרך.

Static site, no build step and no server code: HTML, CSS, JS, fonts and images.
Upload the contents of `kertsman/` to the domain root; every path is relative.

---

## פרסום דירה חדשה / Publishing a new apartment

עורכים קובץ אחד בלבד: **`data/listings.js`**.

1. פותחים את הקובץ ומעתיקים בלוק נכס שלם — מהסוגריים `{` ועד `},`.
2. מדביקים אותו בראש הרשימה (הנכס הראשון מופיע ראשון באתר).
3. מעדכנים:
   - `id`: מזהה ייחודי באנגלית, בלי רווחים (למשל `'ahuza-4'`).
   - `status`: `'available'`, `'under-offer'` (בתהליך) או `'sold'` (נמכר).
   - `exclusive` / `fresh`: `true` כדי להציג את התגיות "בלעדי" ו"חדש".
   - `price`: מספר בשקלים, בלי פסיקים.
   - `rooms`, `size`, `balcony`, `floor`, `floors`, `parking`, `year`.
   - `city`, `area`, `title`, `description`, `features`: טקסט בעברית וברוסית.
   - `images`: נתיבים לתמונות, למשל `['assets/img/my-flat-1.jpg', ...]`.
4. שומרים ומעלים את הקובץ לשרת. הנכס מופיע מיד בשתי השפות, נכנס לסינון,
   למיון, לחיפוש ולנתוני ה-SEO — בלי לגעת בשום קובץ אחר.

להורדת נכס מהאתר: מוחקים את הבלוק שלו, או מסמנים `status: 'sold'` כדי להשאיר
אותו כהוכחת ביצועים.

### תמונות נכס / Property photos

מעלים את הצילומים לתיקייה `assets/img/` ורושמים את שמות הקבצים ב-`images`.
מומלץ יחס 4:3 ורוחב 1600 פיקסלים. התמונה הראשונה היא התמונה שמופיעה בכרטיס.
קובצי ה-SVG שנמצאים שם כרגע הם ממלאי מקום עד שיגיעו הצילומים האמיתיים.

## פרטי המשרד / Office details

בראש `data/listings.js` יש בלוק `KERTSMAN_CONFIG`. **חובה להחליף לפני עלייה לאוויר:**

| שדה | מה לשים | איפה זה מופיע |
| --- | --- | --- |
| `phone` | מספר הטלפון לתצוגה | כפתורי חיוג, פוטר, צור קשר |
| `phoneIntl` | אותו מספר בפורמט בינלאומי, ספרות בלבד (`9725…`) | כל קישורי הוואטסאפ |
| `email` | כתובת מייל לתצוגה. ריק = השורה לא מוצגת | סעיף צור קשר, פוטר |
| `formKey` | מפתח Web3Forms לשליחת הטופס למייל | ראו "טופס יצירת קשר" |
| `licence` | מספר רישיון התיווך. ריק = התגית לא מוצגת | פוטר, סעיף עלינו |
| `serviceArea`, `hours`, `officeCity` | אזור פעילות ושעות מענה | סעיף צור קשר |
| `agent`, `role` | שם העסק ותיאורו | כרטיס הקשר בחלון הדירה |

הטלפון והרישיון כבר מעודכנים. אין כתובת משרד באתר, אלא אזור פעילות בלבד.

## טופס יצירת קשר / Contact form

באתר יש **טופס אחד**, בסעיף "צור קשר". הכפתורים בסעיף "בעלי דירות" מפנים אליו.

**כדי שהפניות יגיעו למייל** (כרגע הן נשלחות בוואטסאפ):

1. נכנסים ל-<https://web3forms.com>, מקלידים את כתובת המייל שאליה הפניות
   אמורות להגיע ולוחצים על יצירת מפתח. המפתח מגיע למייל תוך כמה שניות.
2. מדביקים אותו ב-`data/listings.js`, בשדה `formKey` שבראש הקובץ:
   `formKey: 'כאן-המפתח'`.
3. שומרים ומעלים. מרגע זה כל פנייה מהטופס מגיעה למייל.

כתובת המייל עצמה **לא נמצאת בקוד האתר** אלא שמורה אצל השירות, ולכן היא לא
חשופה למבקרים ולא לסורקים. אם השליחה נכשלת מסיבה כלשהי, הטופס פותח וואטסאפ
עם אותם פרטים כדי שאף פנייה לא תאבד.

**כתובת מייל לתצוגה באתר**: השדה `email` ריק, ולכן שורת המייל לא מוצגת בסעיף
צור קשר ולא בפוטר. מילוי הכתובת בשדה הזה יחזיר אותה לאתר.

## מסך ניהול הדירות / Admin screen

בכתובת `/admin/` יש מסך ניהול בעברית שמאפשר להוסיף דירה, למחוק דירה,
לערוך את כל הפרטים שלה ולשנות את סדר ההצגה, בלי לגעת בקוד.

**סיסמת הכניסה ההתחלתית: `kertsman-admin`. יש להחליף אותה.**
בתחתית מסך הניהול יש כלי קטן: מקלידים סיסמה חדשה, מקבלים שורה מוכנה,
ומחליפים בה את השורה `var PASS_HASH = ...` שבראש `assets/admin.js`.

### איך זה עובד ולמה כך

האתר סטטי לגמרי: אין שרת ואין בסיס נתונים. מסך הניהול עורך את רשימת הדירות
בדפדפן ומייצר מחדש את `data/listings.js`. יש שתי דרכים לפרסם:

**1. פרסום ישר מהאתר (הדרך הרגילה).** בלחיצה על **פרסום לאתר** המסך כותב את
`data/listings.js` ואת התמונות החדשות ישר למחסן הקבצים של האתר, בפעולה אחת.
GitHub Pages בונה מחדש, ותוך כדקה השינוי באוויר. אין מה להוריד ואין מה להעלות.

כדי שזה יעבוד צריך להדביק פעם אחת מפתח גישה, בקטע "חיבור לאתר" שבתחתית מסך
הניהול:

1. נכנסים ל-<https://github.com/settings/personal-access-tokens/new>.
2. תחת *Repository access* בוחרים **Only select repositories** ואת המחסן של
   האתר (`yuli0203/kertsman-site`) — ורק אותו.
3. תחת *Repository permissions* מגדירים **Contents: Read and write**.
   שאר ההרשאות נשארות כפי שהן.
4. בוחרים תאריך תפוגה, יוצרים, ומעתיקים את המפתח (הוא מוצג פעם אחת בלבד).
5. מדביקים אותו בשדה "מפתח הגישה" ולוחצים על **בדיקת החיבור**. הודעה ירוקה
   פירושה שהכול מוכן.

המפתח נשמר בדפדפן שבו הודבק (`localStorage`) ונשלח רק ל-GitHub. לכן מדביקים
אותו במחשב או בטלפון האישי בלבד. בכל רגע אפשר למחוק אותו מהדפדפן בכפתור
שבאותו קטע, ואפשר לבטל אותו לגמרי (Revoke) בהגדרות GitHub — ומאותו רגע הוא לא
יכול לשנות דבר. כיוון שהוא מוגבל למחסן אחד ולהרשאת Contents בלבד, גם אם יגיע
לידיים אחרות אין דרך להגיע דרכו למייל, לדומיין או לשום חשבון אחר.

**2. הורדת העדכון (גיבוי).** אם אין אינטרנט, אם המפתח פג, או אם בעתיד האתר
יעבור לאחסון אחר, לוחצים על **הורדת העדכון**. יורד קובץ ZIP אחד עם
`data/listings.js` ועם התמונות החדשות תחת `assets/img/`, ומעלים את תוכנו
לאותן תיקיות בדיוק בשרת.

היתרון בשיטה הזו: אין תשלום חודשי על מערכת ניהול, האתר נשאר מהיר, וללא מפתח
הגישה אף אחד לא יכול לשנות את האתר מרחוק.

### הגנה על הכניסה

אחרי חמישה ניסיונות שגויים הכניסה ננעלת ל-30 שניות, ואחר כך לזמן שמכפיל את
עצמו: דקה, שתיים, חמש, רבע שעה, עד חצי שעה. בנוסף כל ניסיון לוקח זמן קבוע,
כך שניחוש אוטומטי מתקדם לאט. הנעילה נשמרת בדפדפן, ולכן היא מעכבת בעיקר
ניסיון ידני — מה שמונע נזק אמיתי הוא שאי אפשר לשנות דבר באתר בלי מפתח הגישה,
והוא לא נמצא בקוד האתר אלא רק בדפדפן שבו הודבק.

### מה הסיסמה כן ולא עושה

הסיסמה מסתירה את מסך הניהול ממבקר מזדמן. היא **אינה** אבטחת שרת:
מי שיפתח את קוד המקור של הדף יוכל לעקוף את המסך. מה שבאמת מגן על האתר הוא
מפתח הגישה, שנמצא רק בדפדפן של מי שהדביק אותו: בלעדיו אפשר לערוך במסך, אבל
אי אפשר לפרסם שום דבר לאתר.
מסיבה זו אין להשתמש כאן בסיסמה ששימשה למשהו אחר, ובוודאי לא בסיסמת
האחסון או המייל.

### אם בעתיד תרצו כניסה עם משתמשים אמיתיים

מה שחסר כאן הוא לא השמירה — היא כבר אונליין — אלא ניהול משתמשים אמיתי.
לשם כך צריך אחסון שמריץ קוד צד שרת, או מעבר לאחסון כמו Netlify עם מערכת ניהול
שמחוברת למאגר הקוד. אז הכניסה תהיה עם שם משתמש וסיסמה שנבדקים בשרת, בלי מפתח
גישה בדפדפן.

## מה יש באתר / What the site does

- הירו ברוחב מלא עם תמונת מפרץ חיפה וכניסה מדורגת של הטקסט.
- רשימת הדירות מתקבלת אוטומטית מ-`listings.js`. אין חיפוש ואין סינון,
  כי המשרד מציג מספר קטן של דירות בכל רגע נתון.
- חלון דירה עם גלריה, מפרט מלא, רשימת מאפיינים וכרטיס קשר עם וואטסאפ וחיוג.
- כל הדירות הן למכירה בלבד, באזור חיפה והקריות.
- שתי שפות מלאות, מתג שפה בכותרת, `hreflang` תקין בשני העמודים.
- נתוני `schema.org`: `RealEstateAgent` בכל עמוד ו-`ItemList` של הדירות.
- אנימציות עדינות (סרגל גלילה, כניסת טקסט, ריחוף על כרטיסים) שנכבות
  אוטומטית למשתמשים שביקשו פחות תנועה במערכת ההפעלה.
- מותאם לנייד, ללא גלילה אופקית, עם תמיכה בקורא מסך ובמקלדת.

## בדיקה מקומית / Local preview

```
cd kertsman
python3 -m http.server 8777
```
ואז לפתוח `http://127.0.0.1:8777/` (ו-`/ru/` לגרסה הרוסית).
